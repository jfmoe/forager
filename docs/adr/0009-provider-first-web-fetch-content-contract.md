# Provider-first Web Fetch content contract

Web Fetch returns **Normalized Fetch Content**: provider-independent body Markdown decoded from the successful provider response, without provider transport envelopes or diagnostics. Provider-native extraction remains responsible for choosing the page body; forager does not apply a local semantic denoiser and does not add `--raw` or `--clean`, because a common output shape cannot make three different extraction algorithms choose the same content boundary safely.

**Provider profiles and order:** the shared Web Fetch provider chain is `Tavily → Firecrawl → Jina` for direct fetch, research evidence fetching, search URL validation, and PDFs. Tavily requests complete basic Markdown without query-directed chunks; Firecrawl explicitly requests Markdown with `onlyMainContent: true`; Jina is the completeness-first final fallback, uses the official structured JSON response as the source of body content, and does not enable link removal or generic CSS selectors. There is no content-type-specific provider order.

**Quality and fallback:** the existing `is_thin` gate is unchanged. A decoded body that is empty or too thin becomes a `Quality` attempt and falls through to the next configured provider; if every provider is thin, the chain terminates as Quality. The 4 MiB behavior from ADR 0006 is also unchanged: a truncated body is successful with an explicit diagnostic when its surviving content passes the quality gate, and falls through only when that content is thin.

**Accepted consequences:** provider fallback guarantees a stable payload role and failure model, not byte-equivalent Markdown, identical link sets, or identical main-content boundaries. Jina may return noisier content when the first two providers fail, which is preferable to irreversibly deleting link-list content in the last available result. Provider-specific selectors, browser actions, query-directed chunks, cache/privacy modes, and structured extraction remain explicit task- or site-specific choices rather than defaults.

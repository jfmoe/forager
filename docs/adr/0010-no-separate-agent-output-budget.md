# Keep stdout without a separate agent context budget

Forager will not introduce a separate context-budget layer for successful content output: there will be no character-, byte-, or token-budget flag, default context limit, automatic stdout truncation with full-content spillover, or summary-to-full second-stage retrieval contract. The full rendered result continues to stdout, and `--output` retains its tee semantics. Callers and skills remain responsible for managing long output.

This output decision does not remove the transport and memory safety rails in ADR 0006. Web Fetch alone may turn a UTF-8-safe 4 MiB response prefix into successful Normalized Fetch Content with a truncation diagnostic. Non-Web Fetch protocol responses, including main-search SSE, Exa JSON, and Context7/AnySearch MCP JSON or SSE, must be complete within the 4 MiB hard limit or fail as Runtime without partial output. Non-2xx error bodies remain limited to a 64 KiB head. These fixed limits are not user-configurable context budgets, and a Deadline limits elapsed time rather than replacing byte or memory bounds. This preserves the existing one-shot public CLI contract without making protocol reads unbounded.

# Output redaction scope and response byte caps

**Redaction scope:** redaction guards the surfaces a credential can actually reach: error messages (providers echo bad keys, and reqwest errors embed request URLs), source URLs and titles, journal entries, diagnostics, and config/doctor views. The answer body and fetched page content are exempt: providers cannot know the caller's credentials, so generated or third-party content cannot echo them — a provider that does echo a credential surfaces it through the error path, which stays redacted. Per-delta redaction during SSE accumulation is removed; deltas are appended verbatim. This narrows ADR 0005's "no output or error may contain raw credential characters" to the surfaces listed above, and rescopes acceptance canary H14 accordingly.

**Response byte caps:** every HTTP response read is bounded by hard-coded constants, not config — caps are safety rails against memory exhaustion, not tuning knobs. `MAX_RESPONSE_BYTES` (4 MiB) bounds successful reads: fetch bodies, MCP bodies, and the raw SSE byte stream. `MAX_ERROR_BODY_BYTES` (64 KiB) bounds non-2xx bodies, whose only consumer is a 500-character error message. A shared capped reader over `bytes_stream()` replaces bare `response.text()`; SSE streams are capped at the byte layer, below the eventsource parser, so a single oversized event cannot buffer unbounded. Truncation always lands on a UTF-8 character boundary.

**Truncation semantics:** a truncated fetch or MCP body is a success carrying an explicit diagnostic (`content truncated at 4 MiB`) — the surviving prefix already exceeds what any downstream agent context can consume, and failing over would only re-fetch the same oversized page. An SSE stream that hits the cap is a Runtime `AttemptFailure`: answers are tens of kilobytes, so filling 4 MiB signals runaway generation or a hostile endpoint, and the xAI Responses stream yields its result only in `response.completed`, so a partial stream has no usable result anyway. Error bodies truncate silently at 64 KiB; only their leading 500 characters ever surface, so the cap boundary is never visible. Truncation cannot interact with redaction on exempt surfaces; on redacted error messages the visible portion comes from the head of the buffer, far from the cut.

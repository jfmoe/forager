# 小红书浏览器 route 的真实站点功能矩阵

实测日期：**2026-11-19**，北京时间 21:16–23:24。宿主为 macOS arm64，浏览器为 Managed Browser fingerprint-chromium `148.0.7778.215`。所有运行都使用用户本人扫码登录的小红书 Browser Profile，命令为 `./target/debug/forager`。

本文记录 forager 自己的 `xiaohongshu_browser` 页面逻辑第一次在真实站点上的运行结果：发现了哪些缺陷、如何修复，哪些行为已经证实，哪些仍未验证。可行性探针（不是 forager 的代码）的结果见 [小红书无头指纹浏览器可行性实测](2026-11-18-xiaohongshu-headless-fingerprint-browser.md)；采用这条路径的决定见 ADR 0036。

文中「事实」指存档的命令输出可以复核的内容；「推断」是基于事实的判断；「未验证」是本次没有覆盖的问题。记录中不出现 `xsec_token`、cookie、账号标识，也不出现真实用户的笔记或用户 ID。

## 结论

- **search、fetch、comments 的主要参数组合都通过了（事实）。** 修复两处缺陷之后，矩阵中的每个用例都成功，结果符合所给的筛选条件。
- **首次运行发现两处页面驱动缺陷，只有真实站点能发现（事实）。** 两处都只让命令以 Runtime 失败，没有发出错误输入，也没有返回错误数据。根因和修复见「发现的缺陷」。
- **全天 22 次页面打开都没有出现风控信号（事实）。** 没有登录墙、验证码、频次提示，没有 HTTP 461 或 471，没有 300031 或 300017。
- **用量仍然很小（推断）。** 一个账号、一天、22 次浏览器命令，不能说明持续使用下的风控情况。

## 运行顺序与页面打开次数

1. **门禁检查（6 次，21:16–21:22）**：`doctor --provider xiaohongshu_browser` 深探 1 次，`smoke --live` 中的 C27–C29 共 3 次，重现 C29 失败 2 次（search 1 次、comments 1 次）。C27（search）与 C28（fetch）通过，C29（comments `--replies 1`）失败。
2. **离线修复**：修复 C29 的根因，并根据离线设计审查加固风控分类（#273）与页面操作（#274）。
3. **功能矩阵（16 次）**：分两批跑。第 1 批 22:44–22:48，共 8 次；第 2 批 23:19–23:23，共 8 次，含 1 次修复后的复验。每条命令的完整 stdout 与 stderr 都已存档，所有分析都基于存档，没有为了看另一个字段而重跑。

route 自身的限速（每 10 秒 1 条浏览器命令、并发 1）全程生效。

## 发现的缺陷

### 1. 滚回视口的目标在滚动动画中取了坐标

- **现象（事实）**：C29 和它的重现都在点击第 1 页评论的"展开 N 条回复"时失败，原因为 `target_moved`。原生点击在悬停后复查时，发现指针已经不在目标上，于是放弃按下。
- **根因（事实）**：这时已经读到第 2 页，目标在视口上方很远，原生点击要先用滚轮把它滚回来。Chromium 的滚轮滚动在最后一个滚轮事件之后还会继续动画；在本机页面上采样，最后一个事件之后 50 ms 内，`scrollTop` 从 3830 走到 4000。点击在动画中途取了坐标，悬停结束时目标已经移开。
- **修复**：`fb03493` 让滚轮操作等指针下的滚动区域停止移动后才返回；#274 又加了两条：目标位置连续两次读数一致才取坐标；按下之前复查失败时重新瞄准。新增的真实浏览器测试在修复前 3 次失败 2 次，修复后 10/10 通过。真实站点上，`--replies 3` 与跨页的 `--replies 10` 都通过了。

### 2. 展开过程中自动加载的那一页，其目标被漏掉

- **现象（事实）**：comments 改为边翻页边展开之后（#274），`--limit 20 --replies 10` 在一篇有 7 个可展开评论、分布在两页的笔记上失败，消息为 `read 5 of 7 reply expansions without timing out`，用时 21.2 秒。
- **根因（推断，与现象吻合）**：要点击的目标在评论面板底部，把它滚进视口时，页面自己加载了第 2 页。driver 在展开前只算了一次第 1 页的目标；第 1 页的目标展开完后，它看到已有 2 页，就结束了读取，第 2 页的 2 个目标没有展开。核对环节随后正确地报告了缺失的展开。
- **修复**：`b3e8979` 让 driver 展开完一批后重新计算目标，直到没有未展开的，再决定是否翻页。同一篇笔记、同一组参数复验，7 条都展开了，其中 2 条在第 2 页。
- **测试缺口**：页面驱动逻辑（导航、滚动、点击的先后）没有离线测试，这个缺陷只能靠真实站点发现。见 #279。

## 无头窗口特征

在本机页面上，用一个临时 Browser Profile 读取（不访问站点，也没有用户的 profile）：

- `outerHeight − innerHeight` 为 121，`screenX` 与 `screenY` 为 22。无头窗口没有出现外部尺寸等于内部尺寸的特征。
- `navigator.webdriver` 为 false；UA 是 `Chrome/148.0.0.0`，不含 `HeadlessChrome`；`userAgentData` 的品牌含 `Google Chrome 148`；`navigator.platform` 为 `MacIntel`。
- `Notification.permission` 为 `default`；`document.visibilityState` 为 `visible`。
- `document.hasFocus()` 为 **false**。用户前台正在看的标签页通常为 true；浏览器在后台时也会是 false，所以这个值本身不反常（推断）。
- 临时 profile 没有登录记录，所以屏幕是无头默认值 800×600、设备像素比 1。用户的 profile 会回放登录窗口记录的屏幕尺寸与设备像素比，这由真实浏览器测试 `a_headless_launch_reports_the_screen_recorded_at_login` 覆盖。

## 未验证项

- **合法空集的 search**：随机查询也有模糊匹配的结果，本次没有构造出真正的 0 结果。判定规则由单元测试覆盖。
- **旧版结果页 `/search_result`**：本次所有搜索都落在 `/search_result_ai`，旧版布局的选择器仍然没有被真实页面验证过。
- **分享链接**：不是从搜索结果来的笔记链接（`xsec_source` 不是 `pc_search`），由 route 改写为 `pc_search` 之后能否打开，本次没有测试。
- **风控信号的真实形态**：频次提示的原文、业务接口中 −100、300031、300017 的含义，都没有在真实站点上见到。本次没有出现任何风控信号，这些信号也不能主动诱发，只能等它们自然出现时记录。
- **长期使用**：会话能保持多久，持续使用下的风控情况。

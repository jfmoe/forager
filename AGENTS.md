# forager

A Rust CLI that gives AI agents search, fetch and per-platform retrieval through a chain of providers. Coding agents do almost all of the development here.

## Checks

Run every check command below exactly as written: no pipe, and no `tail`, `head` or `grep` cutting its output. The default profile already prints only failures and the final summary, which names every failed test, and a pipe replaces cargo's exit code with the last command's, so a failed run can look like a pass. An agent that filtered the output lost the name of a failing test.

A change to code is done only after the quick and full checks pass; a change to documents alone needs the documents-only check.

- Quick: `cargo fmt --check && cargo clippy --all-targets --locked -- -D warnings`.
- Full: `cargo nextest run --all-targets --all-features --locked` (install with `brew install cargo-nextest`).
- Documents only: `cargo nextest run --locked --test repository_rules --test skill_contract`.
- One provider or one platform: `cargo nextest run -E 'test(/(^|[:_])(IDS)(_\w*)?::/)'`, with `IDS` as `docs/agents/testing.md` gives it.
- Real-browser tests: the `real-browser` profile, run as `docs/agents/browser-routes.md` describes.
- Test runs use the profiles in `.config/nextest.toml`; without `--profile`, that is `default`.
- CI runs the same configuration through the `ci` profile, and every pull request runs the whole workflow: the quick and full checks on `linux`, and the permission and release artifact gate tests on `windows`.
- After a change to the release scripts, run the release artifact gate, which the default run leaves out, with `cargo nextest run --profile ci --locked --test release_artifact_gate`; `docs/agents/testing.md` says how the local and CI runs differ.
- `git config core.hooksPath .githooks` enables a pre-commit hook that runs `cargo fmt --check`.

A test that fails in the full suite but passes alone depends on something outside itself, such as a real host or another test's state. Find that dependency before closing the task.

## Where each fact goes

Each fact has one owner. When something changes, update the owner and nothing else.

| Kind of fact | Owner |
| --- | --- |
| How it works: constants, limits, algorithms, message text, what a module does | The code |
| What a CLI user can observe: commands, options, output, exit codes, configuration keys | The product skill, `skills/forager/` |
| Why it is this way, and which paths were tried and rejected | An ADR in `docs/adr/` |
| What no single file shows and daily changes do not move | `docs/architecture.md` |
| What a term means and where its boundary is | `GLOSSARY.md` |
| How to do a job in this repository | `docs/agents/` |
| A constraint with none of these homes | A test named after the rule, or a type that makes the violation unwritable |
| Research, live-test records, design drafts, captured source material | `.local/`, untracked |

- **The product skill** ships alone to end users' agents, so it is self-contained. `tests/skill_contract.rs` binds its headings and vocabularies to the CLI definition.
- **`docs/architecture.md`** stops at module groups and names no file, constant or type. A change that adds or removes a module group, or changes a group's job or the dependency direction, updates it in the same commit; review is the only check.
- **`GLOSSARY.md`** holds meanings and boundaries, not module names or values. "Spec" means only the per-change spec in a GitHub issue. An issue is never the source of a current fact: when it ships, each fact it settled lands with its owner above.
- **ADRs** contain only decisions in force:
  - Write one only when the decision is hard to reverse, surprising without its context, and a real trade-off.
  - Sections: a title, then `Decision`, `Why` (with the key evidence figures), `Rejected alternatives`, `Revisit when`, and `Supersedes` when it replaces deleted ADRs. No front matter and no status field.
  - Files are `NNNN-slug.md`. A new ADR, or a part split off an old one, takes the highest number ever used plus one; a merged ADR keeps the newest number it inherits. Numbers are never reused, because commit history, the changelog and old issues cite them.
  - Refer to one as `ADR-NNNN`, one token per number. No values, key names or field names that the code states, and no pointer to another document "for details".
  - Delete a superseded ADR and name it in its successor's `Supersedes` section.
- **`docs/agents/`**: `release.md`, `browser-routes.md` and `testing.md` are procedures. `issue-tracker.md`, `triage-labels.md` and `domain.md` are read by external skills at those paths, so keep the paths; rerunning those skills' setup overwrites them.
- **`CHANGELOG.md`** is generated by release-plz from Conventional Commits during a release; edits by hand are overwritten.

## Writing documents

- Every tracked document and prompt is in English, because this is a public project. Contributors' personal agent settings may ask for another language; this rule wins inside the repository.
- No document restates the code. A copy goes stale without a test noticing, and the next reader cannot tell which version is current.
- Documents carry no change history: no "previously", no migration notes, no leftovers from the session that wrote them. History lives in commits, the changelog and closed issues. An ADR's `Why` may cite dated measurements and figures as its evidence.
- Working material goes in `.local/`; its conclusion goes into an ADR or an issue. `docs/` holds only `architecture.md`, `adr/` and `agents/`, and a rule test enforces that.
- When you retire a route, provider or capability, remove its mentions in the same commit and add its identifier to `RETIRED` in `tests/repository_rules/retired.rs`. A retired approach that a search still finds misleads the next agent. The retired-identifier scan is the retirement's guard, so write no test that proves a retired name is rejected: such a test must name what the scan forbids, and the general rules that reject an undefined command, option or configuration key are proven with invented names.
- A rule written for agents states its reason, so it can be applied where its wording does not reach. Keep absolute wording ("never", "always") for rules with an incident behind them.

## Rust conventions

- Errors are `thiserror` enums; the crate does not use `anyhow` or `Box<dyn Error>`, because error kinds drive attribution and exit codes.
- There is no logging framework. What a run did reaches the user through the stderr attempt log and the journal, both owned by `evidence/`.
- Seam traits are used as trait objects, so their methods return `Pin<Box<dyn Future<Output = …> + Send>>` written out by hand; there is no `async-trait`.
- Unit tests stay inline. When a test module outweighs the code it tests, move it to a sibling `<module>_tests.rs`.

## Rules

- **Read `docs/agents/testing.md` before you add, move or retire a test.** It says which layer a test belongs to, how to add an upstream sample, and what only the real binary can prove.
- **Dependencies point one way**, from the binary down to `types`, as `docs/architecture.md` describes. No test checks this, so a new upward or lateral import is caught only in review.
- **Report the Windows job only from a remote run.** Without a local run there is nothing to report on a non-Windows host; a CI failure or success is the evidence.
- **Fix a compatibility problem in the general mechanism that owns the behaviour**, not with a special case for one site, URL or sample. An agent once reached for a per-domain Web Fetch order where a global order change solved the problem. When a special case seems the only option, discuss it first.
- **Read `docs/agents/browser-routes.md` before you change or live-test a browser route, the browser transport or the Managed Browser.** It holds the stop rules and safety boundaries; a probe loop that kept opening pages through a site block re-triggered the block after it lifted.
- **Adapter work is done only when the changed provider's Live Checks pass** (`forager doctor --live --provider <provider>`), run as `docs/agents/live-checks.md` describes, with the user present for a provider with attended or manual-only checks. The offline tests replay frozen samples and caught none of 37 recorded upstream incidents.
- **Run the platform checklist test (`cargo nextest run --lib platform_checklist`) when you add or change a platform or platform route.** Each failure names the rule it breaks and what to add.
- **Merge to `main` and release by `docs/agents/release.md`**; a release closes only after every step of its completion section, because the next session uses the local CLI, skill and Managed Browser those steps update.
